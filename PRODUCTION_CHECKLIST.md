# Production Checklist

Last reviewed 2026-10-23 against the current working tree. **READY**: current evidence shows it is met. **PARTIAL**: partly met, known work remains. **BLOCKED**: a required control is failing or missing. **NOT VERIFIED**: not enough evidence yet. **NOT READY**: not implemented. **OPTIONAL**: not required for launch.

| Category | Status | Notes |
|----------|--------|-------|
| **Security** | PARTIAL | In place and tested: JWT auth, owner-scoped queries, strict request validation, content-based upload type and size checks (`auth`, `ownership`, `apiConventions` and `documents` tests). **Rate-limit proxy trust (fixed in the working tree, not yet published):** the old default `TRUST_PROXY=1` let a spoofed `X-Forwarded-For` header bypass the sign-in rate limit when no proxy was in front (reproduced 2026-10-23: 12 failed logins, none blocked). It now defaults to 0 outside production, production refuses to start without an explicit value, and blank or invalid values are rejected; the `rateLimitProxy` regression tests cover rotating spoofed headers and limit enforcement, and pass locally. The correct hop count for the real hosting proxy is not yet verified. **Dependencies:** the working-tree lockfile has `proxy-addr` 2.0.8 instead of 2.0.7 (not yet published; the targeted and full backend tests pass with it). The `pdfjs-dist` advisory is still open (needs a major upgrade; mitigated with `isEvalSupported: false`), so the production audit is not clean. Tokens cannot be revoked. **Next:** publish the fix and the patch, set and verify `TRUST_PROXY` on the real host, plan the `pdfjs-dist` upgrade. |
| **Environment** | PARTIAL | `server/.env.example`; startup fails in production without `MONGO_URI` and a real `JWT_SECRET` (`configAndLogging` tests); in the working tree (not yet published) it also fails without an explicit `TRUST_PROXY`. **Gaps:** production starts without `CLIENT_URL`/`CORS_ORIGINS` and silently allows only `http://localhost:5173`; there is no `client/.env.example`, and a frontend build without `VITE_API_BASE_URL` silently calls `http://localhost:5000`. **Next:** require these values for production builds and starts. |
| **Database** | PARTIAL | External MongoDB; `analyses` indexed by owner and `users.email` unique; startup fails fast when the database is unreachable. Tested only against in-memory MongoDB. **Not verified:** a hosted database (connection, TLS, least-privilege user, network access, index creation). **Next:** provision it and check `/api/health/ready`. |
| **Testing** | PARTIAL | Jest suite for the backend, in-memory MongoDB, no credentials needed. Last full run: 22/22 suites, 442/442 tests, exit code 0 (2026-10-23, Node.js 22.20.0, run locally against the working tree, including the new `rateLimitProxy` regression tests). Also validated locally on Node 22.20.0: the frontend production build succeeds, and PDF extraction matches the earlier Node 20 baseline apart from the Node/V8 version fields and is deterministic across repeated runs. The frontend has lint and a production build, no automated tests. No regression tests yet for the known JD-parsing false positives (offered visa sponsorship, "will be", "MS Office", "Associate Engineer"). **Next:** a full run in Linux CI once the changes are published. |

Node.js 22 is pinned in the working tree (`engines`, `.nvmrc`, `node:22-slim`) but not yet published, and installing on Linux is unverified. **Next:** fix these, then deploy to a restricted environment and run smoke tests. |
